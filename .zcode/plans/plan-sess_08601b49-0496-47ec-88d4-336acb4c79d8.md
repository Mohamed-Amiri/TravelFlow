## SafariHub Backend — Production Audit & Fix Plan

### Summary
15 issues found (3 Critical, 10 Major, 2 Minor, 5 Suggestions). All Critical and Major issues will be fixed automatically. No breaking API changes.

### CRITICAL Fixes

**C1. Race condition on seat booking**
- Add `@Version private Long version;` to `BaseEntity.java` (enables optimistic locking for all entities)
- Add `ObjectOptimisticLockingFailureException` → HTTP 409 handler in `GlobalExceptionHandler.java`
- Message: `"Concurrent modification detected — please retry"`

**C2. Reservation unique constraint mismatch**
- Change `Reservation.java` unique constraint: `columnNames = {"user_id", "trip_id", "status"}`
- This allows one CONFIRMED + one CANCELLED per user-trip, matching the service logic

**C3. Trip deletion with active reservations**
- In `TripServiceImpl.deleteTrip()`, add check: query `ReservationRepository.countByTripIdAndStatus(tripId, CONFIRMED)` > 0 → throw `BadRequestException("Cannot delete trip with active reservations")`
- Add `countByTripIdAndStatus(Long tripId, ReservationStatus status)` to `ReservationRepository`
